# Training

Train a new `b8c64-v2` network directly from a raw C++ replay `.bin` file:

```sh
python3 training/train.py \
  --data data-202611171329.bin \
  --epochs 5 \
  --lr 0.01 \
  --output-network gen1.onnx
```

Only `--data` and `--epochs` are required. `--lr` defaults to `0.01`, `--batch` to `256`,
and `--output-network` to `model.onnx`.

## Options

| Option | Default | Meaning |
|---|---:|---|
| `--data`, `--replay` | required | Raw replay `.bin` file generated by the C++ engine |
| `--epochs` | required | Full passes over the training split |
| `--lr` | 0.01 | Initial SGD learning rate |
| `--batch` | 256 | Positions per update |
| `--output-network` | model.onnx | Output ONNX network |
| `--seed` | 20260910 | Training RNG seed |
| `--device` | auto | `cuda`, `mps`, or `cpu` |

The number of updates is:

```text
ceil(train_samples / batch) * epochs
```

The trainer auto-selects CUDA, MPS, or CPU. It starts from a random `b8c64-v2`
initialization, trains WDL and disc-margin heads, and exports the final ONNX network
with metadata for the C++ engine. To load it with UCI, build Islay with ONNX Runtime
enabled (`-DISLAY_ONNX=ON` and `-DONNXRUNTIME_ROOT=/path/to/onnxruntime`); the default
build has ONNX support disabled. Then use `setoption name EvalFile value /path/to/model.onnx`.
